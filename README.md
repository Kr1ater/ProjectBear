# Dead Air — лут, инвентарь и разборка

Тестовое задание, вариант 1. Система лута и инвентаря с лимитом по весу, авто- и ручным подбором, янтарными скобками над лутом и разборкой хлама прямо из инвентаря.

- **Unity:** 6000.3.6f1 (Unity 6.3 LTS), URP, Input System.
- **Сцена:** `Assets/_Project/Scenes/LootDemo.unity`, она же первая в Build Settings.

## Управление

| Действие | Клавиша |
| --- | --- |
| Движение | WASD |
| Камера | Мышь |
| Подобрать предмет в фокусе | E |
| Открыть / закрыть инвентарь | Tab |
| Выбрать предмет в списке | ЛКМ |
| Разобрать выбранный хлам | X или кнопка «Разобрать» |
| Выбросить 1 шт. выбранного предмета | G или кнопка «Выбросить» |

Пока открыт инвентарь, курсор свободен, движение, камера и подбор отключены.

## Что сделано

| Требование ТЗ | Как устроено |
| --- | --- |
| Предметы — данные в ScriptableObject | `ItemDefinition`: категория, вес, размер стопки, способ подбора, компоненты разборки, модель для мира, иконка. 11 ассетов в `Data/Items`. |
| Четыре категории | `ItemCategory`: Consumable, RepairResource, Junk, Weapon. |
| Лимит по весу, игрок видит причину | `Inventory.TryAdd` возвращает `AddResult` со статусом `Ok`, `Partial` или `Overweight`. В HUD появляется «Перегруз: Карабин — нужно 6.0, свободно 2.4», шкала веса вспыхивает янтарным. На скорость вес не влияет. |
| Авто- и ручной подбор задаётся в данных | Поле `pickupMode`. Auto-предметы подбираются ближе 1.5 м. Manual — по E, только предмет в фокусе: в радиусе 2.5 м, ближайший к центру экрана и к игроку. |
| Янтарная скобка над лутом, без обводок в мире | `LootMarkers` рисует скобки на Canvas в радиусе 6 м. Скобки берутся из пула. Предметы за препятствием не подсвечиваются (Linecast от камеры). У предмета в фокусе скобка крупнее и ярче, рядом подпись «[E] Подобрать: …» с весом. |
| Разборка хлама из инвентаря | `SalvageService` разбирает одну единицу за раз по принципу «всё или ничего»: если компоненты не влезут, ничего не меняется. |
| Простой интерфейс списком | Список стопок с весом каждой строки, вкладки по категориям, панель деталей, шкала веса. |

Сверх ТЗ:

- **Частичный подбор стопки.** Если из 10 болтов влезает 6, игрок берёт 6, а 4 остаются на земле: «+6 Болты (не хватает места для 4)».
- **Автоподбор без спама.** Сообщение о перегрузе при автоподборе выводится один раз, пока игрок не отойдёт от предмета.
- **Выброс из инвентаря.** `ItemDropper` убирает одну единицу и кладёт модель предмета на землю перед игроком: предмет вылетает из рюкзака и вырастает из нуля. Выброшенное подбирается только по E, даже если в данных стоит автоподбор, — иначе оно вернулось бы в инвентарь с первым же шагом.
- **Анимация подбора.** Подобранный предмет не исчезает, а притягивается к рюкзаку с разгоном и последнюю треть пути сжимается в ноль (`ItemFlight`). Если взята только часть кучки, к рюкзаку летит её копия, а кучка остаётся.
- **Плавные скобки.** Скобка проявляется за 0.25 с и «сходится» на предмет из увеличенного размера, при пропаже гаснет на последнем месте. Переход фокуса и подпись «[E] Подобрать» тоже плавные.
- **17 Edit Mode тестов.** Они покрывают инвентарь, разборку и проверку всех ассетов, включая числа из сценария видео.

## Формат данных: как добавить предмет

1. ПКМ в `Assets/_Project/Data/Items` → **Create → Dead Air → Item Definition**.
2. Заполнить поля:

| Поле | Смысл |
| --- | --- |
| `id` | Уникальный ключ |
| `displayName`, `description` | Тексты для UI |
| `icon` | Спрайт для списка |
| `category` | Consumable / RepairResource / Junk / Weapon |
| `weight` | Вес одной единицы, больше 0 |
| `maxStack` | Сколько единиц в одной стопке |
| `pickupMode` | Auto или Manual |
| `salvageResult` | Список «предмет + количество». Только у хлама. |
| `worldPrefab` | Модель для мира с компонентом `WorldItem` |

3. Чтобы положить предмет на сцену, поставить его префаб (или любой объект с `WorldItem` и коллайдером-триггером на слое `Loot`) и указать количество в `WorldItem.amount`.

Код при этом не меняется. Правила данных проверяются в `ItemDefinition.Validate`: предупреждения выводятся в консоль при правке ассета, тест `AllItems_PassValidation` проходит по всем ассетам. Правила такие:

- вес больше 0, стопка не меньше 1;
- у хлама список разборки не пустой, у остальных категорий пустой;
- компоненты весят меньше самого предмета, поэтому разборка всегда освобождает место.

## Архитектура

```
Assets/_Project/
  Scripts/
    Items/      ItemDefinition, ItemAmount, ItemCategory, PickupMode — данные
    Inventory/  Inventory, ItemStack, AddResult, SalvageService — логика, чистый C#
    World/      WorldItem — предмет на земле, ItemFlight — полёт к рюкзаку и из него
    Player/     PlayerInventory, LootSensor, ItemDropper, InputReader, PlayerController, ThirdPersonCamera
    UI/         HudUI, LootMarkers, MessageFeed, WeightBar, InventoryUI, InventoryRow, ItemDetailsPanel, CategoryTab
  Tests/EditMode/   тесты инвентаря, разборки и ассетов
  Editor/           генератор демо-контента (см. ниже)
  Data/Items/  Prefabs/  Art/  Input/  Scenes/
```

- **Логика отдельно от Unity-объектов.** `Inventory` и `SalvageService` — обычные C#-классы, о сцене и UI ничего не знают, поэтому их легко тестировать.
- **Мир и UI только вызывают логику и подписываются на события.**
  - `LootSensor` подбирает предметы через `TryAdd`.
  - UI узнаёт об изменениях из события `Inventory.OnChanged`.
  - Разборка проходит через `SalvageService`, а он вызывает атомарный `Inventory.TryExchange`: одна проверка, одно событие.
  - Выброс проходит через `ItemDropper`: он вызывает `Inventory.Remove` и создаёт предмет в мире.
- **`PlayerInventory`** — точка входа на сцене. Лимит веса задаётся в инспекторе. Компонент создаёт `Inventory` и `SalvageService` и отдаёт их сенсору и UI.
- **`InputReader`** — единственный класс, который знает про Input System. Остальные берут значения и события у него.
- **Без синглтонов и `FindObjectOfType`.** Все ссылки проставлены в инспекторе.
- **Тексты сообщений собираются в `UiText`.** Логика возвращает только статусы и числа.

## Тесты

**Window → General → Test Runner → EditMode → Run All.**

Сборка `DeadAir.Tests.EditMode` содержит 17 тестов, все проходят. Среди них сценарий из видео на настоящих ассетах:

1. Автоподбор: вес 2.6.
2. Рация, насос и 2 картриджа: вес 12.6.
3. Карабин (6.0) не влезает.
4. После разборки рации и насоса вес 6.9.
5. Карабин подбирается.

## Демо-сцена и сценарий видео

Сцена — грейбокс 30×30 м: место крушения грузового модуля, ржаво-красный грунт, два солнца. Белое даёт жёсткие тени, красное подкрашивает тени тёплым.

Лут разложен «дорожкой» от точки старта:

1. Болты, изолента и медпакеты подбираются автоматически: вес 2.6.
2. Рация, насос и 2 кислородных картриджа подбираются по E: вес 12.6.
3. Карабин на ящике не влезает: «нужно 6.0, свободно 2.4».
4. Разбираем рацию и насос в инвентаре: вес 6.9.
5. Карабин подбирается.

В стороне от маршрута лежат остальные предметы: проводка, микросхемы, пластины, пустые баллоны. Там же, слева, куча из 40 болтов для демонстрации частичного подбора.

**Генератор.** Ассеты предметов, префабы, иконки и сцену собирает editor-скрипт: **Tools → Dead Air → Rebuild Demo Content**.

- Модели собраны из примитивов, иконки отрендерены из этих же моделей.
- Повторный запуск перезаписывает файлы на тех же путях.
- После ручных правок в сцене или ассетах генератор запускать не нужно: он их перезапишет.

## Ассеты и нейросети

- **Сторонних ассетов нет**, кроме шрифта Inter, который требует гайд проекта.
  - Модели предметов, героя и окружения собраны из примитивов Unity.
  - Иконки отрендерены из этих моделей.
  - Спрайт скобки нарисован кодом.
- **Шрифт:** Inter 4.1 (Regular) из [официального релиза](https://github.com/rsms/inter/releases/tag/v4.1), лицензия SIL OFL 1.1.
  - Файлы: `Art/Fonts/Inter-Regular.ttf`, текст лицензии — `Art/Fonts/Inter-OFL.txt`.
  - Font Asset `Inter-Regular SDF` динамический и назначен шрифтом по умолчанию в TMP Settings.
  - LiberationSans из TMP Essentials оставлен запасным шрифтом.
- **Нейросети:** _заполнить — например, Claude Code: помощь в коде и в генераторе сцены._
